# BeanFinder v2.0.0

Release candidate; tag and GitHub release publication are pending. This file is the prepared release-note body.

BeanFinder v2 makes the Australian directory easier to search and use on a phone, improves cafe discovery on the map, and keeps community updates behind validated review PRs.

## Directory and design

- Refreshed coffee/cream branding, persistent light/dark themes, responsive rows and multi-location disclosures.
- Full-directory search, state/cafe filters and A–Z/highest/lowest saved-rating sorting before pagination; 12 roasters per page with bookmarkable URLs and accessible results navigation.
- Separate comparison for eight multi-roaster sellers, with subscription, selection and brew information.
- Consolidated 239 unique businesses: 231 roasters and eight sellers. Stable identities, website aliases, reviewed branch sources and shared data validation prevent duplicate/misclassified records.
- Legacy state/cafe/page links redirect to filtered directory URLs; old multi-roaster filters redirect to the seller comparison.

## Maps and privacy

- Australian location autocomplete, cafe-only discovery by default and optional explicit geolocation with manual-search fallbacks.
- Keyboard-accessible markers/clusters, current Australian addresses on selection, provider attribution and place-specific Maps/directions links.
- Reserved map loading/error space and a directory fallback, including without JavaScript.
- Separate browser/server keys and bounded requests: 20 Place Details attempts per mounted map; a production worker with at most 1000 coordinate attempts per UTC month, four per hourly batch and two concurrently.
- Newly retrieved coordinates renew from day 27 and expire after 29 days, with independent cleanup. No weekly full-directory rediscovery or permanent provider enrichment.
- Public privacy/terms pages; Google Analytics removed. Location remains transient and is requested only on activation.

## Contributions and sharing

- Recommendations/corrections produce review PRs with immutable business identities, whitelisted receipts, source/provenance and atomic data/version changes.
- Required `verify` checks, current-main patch validation, duplicate-event handling, replay/backfill and token/failure recovery.
- Route-specific titles/descriptions, canonical URLs, sitemap/robots and a new BeanFinder social image with Open Graph and large-image card metadata.
- Brief README, separate contributing/operations guides and current production screenshots.

Single lab measurements do not represent field Core Web Vitals. Exact coverage and omitted production form-error activation are recorded in [release verification](../release-verification.md).

## Maintainer upgrade notes

The app and both lockfile roots move from `1.1.0` to `2.0.0` without changing dependency versions. Builds/CI use the pinned Node 26.10.0. Subsequent reviewed data changes propose `2.0.1`, then `2.0.2`; pending form PRs must be reconciled against current main before merge. Runtime coordinates do not create release bumps.

Use separate `GOOGLE_MAPS_API_KEY` and `GOOGLE_PLACES_SERVER_API_KEY` credentials, enable Places API (New), and keep the production worker allowance and form token in the Functions environment. Preview coordinate access stays isolated. See [CONTRIBUTING](../../CONTRIBUTING.md) and [operations](../operations.md) for setup and recovery.

Saved ratings and the accepted legacy map snapshot have unknown historical retrieval dates and remain by maintainer decision. Cafe flags are curated information; verify access/hours with the operator. Existing Netlify development/build dependency advisories were accepted for this release and remain deferred; see the [decision record](../maps-release-polish.md#dependency-advisory-decision-record). Live ratings/counts, a general database migration and a PWA are outside this release.
